01 What is healthy

The audit found real strengths worth naming first — several practices here are better than most projects of this size.

  • Schemas and runtime validators are coupled: schemas/README.md accurately maps each JSON schema to its validator and emission point. This is the most reliable doc in the repo.
  • Canonical single-source vocabulary: claim statuses/aliases in docs/income-ops.md are consistent across the ADR, runbooks, PROJECT_CONTEXT, and CHANGELOG.
  • Runbooks carry explicit allow/deny lists per stage — genuine safety documentation, not boilerplate.
  • CHANGELOG.md is disciplined and is the de-facto feature reference; benchmark targets are consistent across every doc that cites them.
  • Artifact-first agent contract: handoff_package.json as primary entrypoint, validated on export, with a defined read order in AGENTS.md.

04 Critique — how this repo serves an AI agent

Assessed as: a cold-start AI agent (Claude Code, Cursor, Codex) lands in this repo and must decide what Scout is, what it can do, and how to operate it safely.

What already works well

  • AGENTS.md gives a correct read order for session artifacts — the first thing a coding agent needs.
  • Artifact-first contract: handoff_package.json + scout_session.json tell an agent what happened without reading source.
  • Runbooks with deny-lists — the safety model is discoverable, not implied.
  • Self-validating outputs: exports validate by default; schemas and validators stay in lockstep.
  • CHANGELOG is a true history — the single most reliable doc in the repo for feature archaeology.

Where an agent gets lost

  • No repo map: the agent must synthesize six docs to learn what exists; src/ has no overview anywhere.
  • Four competing version truths (banner / package / PROJECT_CONTEXT / branch name).
  • The primary runbook teaches a no-op flag (--safe) and a dead preset — following docs produces wrong behavior.
  • Research docs indistinguishable from current ones — an agent can design against superseded specs (SCOUT_HANDOFF_SCHEMA never existed).
  • Docs and data share the root namespace: generated reports pollute search results; an agent globbing *.md can’t tell documentation from output.
  • Key income-path contract underdocumented: AGENTS.md & discovery-runbook describe only schema 1.1 — the beginner lane — while the primary use is rewarded cash-in on 1.2.
Verdict

The documentation is unusually good for a personal tool — but it is written for someone who already knows the system, and the entry points serve the beginner lane while the product lives in the rewarded lane. The drift is not decay from neglect; it is the cost of fast shipping with docs spread across six files that each restate the same facts. Every high-severity failure an agent would hit is fixed by deleting or dating stale statements, not by writing more.
